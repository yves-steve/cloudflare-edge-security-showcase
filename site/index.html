01 / REQUEST ROUTE

The origin never waits for strangers.

The connector calls outward first. Visitor requests cross the edge only after Cloudflare has terminated TLS and applied the zone's controls.

  1. 01 Visitor Requests the public hostname over HTTPS.
  2. 02 Cloudflare edge Terminates TLS, filters traffic, and serves cache hits.
  3. 03 Encrypted Tunnel Uses connections initiated by cloudflared.
  4. 04 Private origin Nginx serves static files on loopback port 8080.
↳

Trust boundary: Cloudflare is the only public application entry point. The GCP firewall has no inbound allow rule.

02 / CONTROL PLANE

Protection in layers, with the limits left visible.

IDENTITY

DNS as code

Proxied records reference the Tunnel resource, so teardown order is explicit and dangling records are less likely.

Terraform managed
CONFIDENTIALITY

Automatic edge TLS

Universal SSL handles the browser certificate while HTTPS redirects and a TLS 1.2 minimum are enforced at the zone.

Free plan baseline
AVAILABILITY

DDoS and cache

Cloudflare's standard DDoS systems sit in front of a cache-friendly static origin, reducing work that reaches the VM.

Always-on edge
APPLICATION

Static-only WAF rule

GET and HEAD are expected. Other methods are blocked until a future form or API is reviewed and intentionally enabled.

One custom rule
What this design does not promise

Cloudflare protects traffic that actually passes through Cloudflare. Leaked credentials, unsafe application code, compromised cloud accounts, and stale third-party resources require separate controls.

Security Insights can detect suspicious DNS state, but periodic detection is not prevention. The repository keeps decommissioning order reviewable and still expects a human to verify the final DNS state.

03 / DELIVERY

Manual where ownership matters. Automated where drift matters.

Buy the domain and delegate nameservers with a human in the loop. Then let a reviewed Terraform plan build the network, VM, Tunnel, DNS records, and edge settings.
